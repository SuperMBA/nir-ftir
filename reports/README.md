# Итоговые результаты

Эта папка содержит компактные итоговые таблицы, используемые в магистерской ВКР по теме:

**«Аугментация ATR-FTIR-спектров биологических жидкостей: сравнительная оценка, геометрия данных и устойчивость выводов»**

В репозиторий включены только финальные таблицы и figure-ready результаты, необходимые для проверки основных выводов работы. Полные run-level JSON-отчёты, промежуточные артефакты, временные папки экспериментов и тяжёлые результаты запусков не версионируются, чтобы не перегружать репозиторий.

## 1. Saliva datasets: supervised baseline → augmentation

### Файлы

- `covid_saliva_supervised_deltas.csv` — изменение supervised-метрик для COVID saliva при сравнении baseline и train-only classic augmentation.
- `diabetes_saliva_supervised_deltas.csv` — изменение supervised-метрик для diabetes saliva при сравнении baseline и train-only strong augmentation.
- `saliva_supervised_deltas.csv` — объединённая таблица по COVID saliva и diabetes saliva.
- `saliva_supervised_summary.md` — компактная markdown-сводка для чтения и вставки в текст работы.

### Интерпретация столбцов

- `delta_pr_auc > 0` — улучшение PR-AUC.
- `delta_recall > 0` — рост чувствительности.
- `delta_f1 > 0` — рост F1-меры.
- `delta_specificity` — изменение специфичности; отрицательное значение может показывать цену роста чувствительности.
- `delta_brier < 0` — улучшение Brier score, то есть вероятностной калибровки.
- `delta_ece < 0` — улучшение Expected Calibration Error.

### Основной вывод

На более крупных saliva-наборах аугментация чаще работает как умеренный регуляризатор supervised-моделей. Эффект не является универсальным для всех моделей, но в ряде случаев повышает Recall, F1, PR-AUC и улучшает калибровку.

Особенно выраженный положительный эффект наблюдается на diabetes saliva для модели SVM-RBF: рост PR-AUC, Recall и F1 сопровождается улучшением Brier score и ECE. Для COVID saliva эффект более умеренный и модель-зависимый.

## 2. GDB small-n: PCA / factor–PC associations

### Файлы

- `gdb_dimdesc_window_summary.csv` — сводка по спектральным окнам и изменению factor–PC associations после аугментации.
- `gdb_dimdesc_best_pc_per_factor.csv` — best-PC таблица по клиническим факторам.

### Основной вывод

На малом наборе GDB small-n классическая аугментация наиболее заметно меняет геометрию данных в локальном окне **Amide III**. На широких спектральных диапазонах эффект существенно слабее.

Это означает, что для very small-n данных supervised-метрики сами по себе недостаточны: даже если качество классификации меняется нестабильно, аугментация может заметно менять структуру спектрального пространства.

Важно: PCA-компоненты здесь не интерпретируются напрямую как биологические маркеры. Они используются как инструмент проверки того, как аугментация меняет геометрию данных и распределение связи клинических факторов с компонентами.

## 3. GDB small-n: synthetic-data QC

### Файлы

- `gdb_qc_amide3_method_summary.csv`
- `gdb_qc_amide3_label_method_summary.csv`
- `gdb_qc_broad_method_summary.csv`
- `gdb_qc_broad_label_method_summary.csv`

Эти таблицы используются для контроля качества синтетических данных и сравнения baseline / classic augmentation / VAE в малом клиническом наборе.

### Основной вывод

Синтетические данные нельзя оценивать только визуально или только по росту одной supervised-метрики. Для small-n задач необходим отдельный контроль качества синтетики.

Используемые QC-показатели:

- `real-vs-synth AUC` — насколько легко отделить реальные спектры от синтетических;
- `kNN overlap` — насколько синтетические объекты расположены рядом с реальными в локальной структуре данных;
- `Wasserstein distance` — насколько сильно распределение синтетических данных отличается от реального;
- downstream sanity-checks — проверка, не создаёт ли синтетика ложный supervised-оптимизм.

Основной методический вывод: рост Recall, F1 или PR-AUC после аугментации должен интерпретироваться только вместе с QC синтетических данных, калибровкой и устойчивостью по seed.

   Показывают, что качество синтетических данных должно проверяться отдельно, особенно в very small-n задачах.
